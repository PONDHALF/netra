# NETRA — สถานะโปรเจกต์ (อ่านไฟล์นี้ก่อนเริ่มงานทุกครั้ง)

> **อัปเดตล่าสุด: 2026-09-30** — ทุกครั้งที่จบงานหรือก่อน exit ให้แก้ไฟล์นี้ให้ตรงกับความจริง (วันที่, ทำอะไรไปแล้ว, เหลืออะไร) แล้ว commit
> ภาพรวมแผนเต็มอยู่ที่ [plan.md](../plan.md) — ไฟล์นี้บอกว่า **ตอนนี้อยู่ตรงไหนของแผน**

## สรุปหนึ่งย่อหน้า
ระบบอ่านป้ายทะเบียนไทยจากกล้องสดทำงานได้จริงบนเครื่อง Windows RTX 3060: จับรถ → หาป้ายในกรอบรถ → อ่านด้วย PlateNet (เทรนเอง) + char-OCR → บันทึก event และแสดงภาพสดพร้อมกรอบผ่านเว็บ (LL-HLS) ตอนนี้ได้ ~28–29 fps จากเป้า 30 fps และกำลังเตรียมย้ายเครื่องประมวลผล (เครื่อง RTX 3060 เครื่องนี้จะหมดอายุ) — สำรองโมเดล/ข้อมูลเทรนไว้ที่ Mac แล้ว

## เครื่องและการทำงาน
| เครื่อง | หน้าที่ | หมายเหตุ |
|---|---|---|
| Mac (M5, RAM 16 GB) | พัฒนา, สั่งงานเครื่อง Windows ผ่าน SSH | `.deploy.env` (ไม่อยู่ใน git) เก็บ `WIN_HOST`/`WIN_USER`/`WIN_DIR` |
| Windows RTX 3060 12 GB | รันจริง (Docker GPU), เทรน | **จะหมดอายุ** — ดู "การย้ายเครื่อง" ด้านล่าง |

คำสั่งหลัก: `make deploy` (push + build + รีสตาร์ท) · `make remote-status` · `make remote-logs` · `make remote-train TRAIN_ARGS=...` · เทรนต้องหยุด Live ก่อน (`stop netra camsim`) แล้วเปิดกลับเมื่อจบ

## ทำเสร็จแล้ว
- **Phase 1 (อัปโหลดวิดีโอ):** engine ตรวจจับ/ติดตาม/อ่านป้าย, backend + WebSocket, หน้าเว็บ (Upload, Job, Search, Event, แก้เลขด้วยมือ, export), Docker
- **Docker GPU บน Windows + TensorRT** (YOLO11s, plate detector) — deploy จาก Mac ด้วย `make deploy`
- **PlateNet** (CRNN+CTC อ่านป้ายทั้งแถว + จังหวัด 77 คลาส) เทรน 4 รอบ: `platenet` → `-ft1` → `-real1` (ป้ายจริง) → `-night1` (โหมดกลางคืน, **ใช้งานอยู่**) — ดู [TRAINING-RESTORE.md](TRAINING-RESTORE.md)
- **กล้องสด (Phase 2 บางส่วนที่ทำล่วงหน้า):** เพิ่ม/เริ่ม/หยุด/ลบกล้อง RTSP ในหน้า Live, กล้องจำลอง (`camsim` เล่นคลิป 10 นาทีวน), event เด้งขึ้นหน้าเว็บผ่าน WebSocket, auto-reconnect
- **หาป้ายในกรอบรถ** (`NETRA_PLATE_MODE=crops`): เร็วขึ้น 34% และอ่านตรงเฉลยเพิ่มจาก 68% → 94% เมื่อเทียบเฉลยอัตโนมัติ
- **Live 30 fps เป็นค่าเริ่มต้น** (งานวิดีโออัปโหลดยัง 15 fps) + **pipeline 2 ขั้น** (`NETRA_PIPELINE`) เร็วขึ้น ~12% (31.5 → 27.7 ms/เฟรมใน bench)
- **ภาพสดบนเว็บแบบ H.264 / LL-HLS** ผ่าน MediaMTX (พอร์ต 8888, path `annot<cam_id>`, ~3 Mbps, ดีเลย์ ~1–2 วินาที) — ผู้ใช้ยืนยันว่าเล่นลื่นในเบราว์เซอร์; ถอยไปใช้ MJPEG อัตโนมัติถ้า HLS ไม่ติด; ปิดได้ด้วย `NETRA_HLS_RTSP=0`; วัด A/B แล้วไม่ทำให้ fps ตก (28.7 ปิด / 28.6 เปิด)
- **เครื่องมือวัด:** `training/stream_bench.py` (ความเร็วต่อขั้น + ความแม่นยำเทียบเฉลย), `make bench` (thai-parking-100)
- **สำรองข้อมูลเทรน** ไว้ที่ `data/backup-win/` บน Mac (2.9 GB: checkpoint 4 รอบ, real-plates, ชุดข้อมูลดิบ, netra.db, benchmark, `MANIFEST.txt` มี hash)
- UI polish (Search/Event/Live), เอกสารตั้งเครื่อง [WINDOWS.md](WINDOWS.md)

2. **Live ให้นิ่ง 30 fps** — ทางที่ยังไม่ได้ทำ: ตรวจจับรถทุก 2 เฟรมแล้วให้ tracker เติมช่วงกลาง; ลดงาน postprocess/ByteTrack (สาเหตุที่ pipeline ได้ผลน้อยกว่าคาดยังไม่พิสูจน์ — สงสัยค่าใช้จ่ายไดรเวอร์ GPU บน WSL2) ทางที่ตัดทิ้ง: ย้ายเตรียมภาพ/ถอดรหัสไป GPU (วัดแล้วประหยัดได้แค่ ~2 ms)

4. **งานวิดีโออัปโหลดยังใช้ 15 fps + หาป้ายทั้งภาพ** (ไม่ได้ใช้โหมด crops/pipeline) — ถ้าจะให้แม่นขึ้นค่อยเปิด
5. **วัดความแม่นยำ PlateNet รุ่น night1 ใหม่** บน thai-parking-100 (`make bench`) แล้วอัปเดต README
6. **Phase 2 ที่ยังไม่เริ่ม:** Watchlist + แจ้งเตือน, ผู้ใช้/สิทธิ์/Audit log, รายงานรายชั่วโมง/วัน, ค้นหาป้ายแบบใกล้เคียง + Timeline, PostgreSQL/MinIO/Redis, ทดสอบหลายกล้อง/24 ชม., Monitoring, เอกสาร PDPA (ดู plan.md ส่วน 2.5–2.9)

## ข้อควรรู้ / ข้อตกลงที่ผู้ใช้ตั้งไว้
- ตอบเป็นภาษาไทยเสมอ
- ระหว่างเทรนบนเครื่อง Windows ให้หยุด Live (`docker compose ... stop netra camsim`) แล้วเปิดกลับเมื่อเทรนเสร็จ
- ไฟล์ `.bat` ต้องเป็น ASCII + CRLF
- ข้อมูลกล้องจริงมีภาพป้ายทะเบียน — ถามผู้ใช้ก่อนคัดลอก/อัปโหลดไปที่อื่น
- ffmpeg ของ imageio-ffmpeg (static) พัง (segfault) ถ้าให้แปลงชื่อโฮสต์เอง — `backend/app/hls.py` แปลงเป็น IP ก่อนแล้ว
- สคริปต์ที่ต้องส่ง argument หลายตัวใน zsh: ตัวแปรที่ไม่ใส่ `"..."` ไม่ถูกแยกคำ (เคยทำให้วัด A/B ผิดไปหนึ่งรอบ)
